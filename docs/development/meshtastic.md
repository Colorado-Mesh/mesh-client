# Meshtastic channel URLs & Store & Forward

Developer reference for Meshtastic config apply, admin, channel URLs, Store & Forward, remote admin, last-heard, or static GPS. Repo-wide rules live in [`AGENTS.md`](../../AGENTS.md).

- **Config apply (Radio / Modules / Security):** Firmware `setConfig` / `setModuleConfig` replace full protobuf structs. UI must merge cached device slices with form edits via `meshtasticConfigApply.ts` (`mergeMeshtasticConfigApplyValue`, `buildMeshtasticModuleApplyValue`); slices live in `deviceStore.meshtasticConfigSlices` and `moduleConfigs` (PacketRouter + runtime lifecycle wire effects). Module-specific validation: `meshtasticMqttModuleApply.ts`, `meshtasticSerialModuleApply.ts`. Apply failures surface `clientNotification` text within 8s (`meshtasticClientNotification.ts` → `formatMeshtasticModuleApplyError`); inline status via `ConfigApplyNotice.tsx`. Forms re-sync after reboot via `useSyncFormFromConfig`.
- **Administration tab:** `AdminPanel.tsx` — device commands and Danger Zone (reboot, shutdown, factory reset, NodeDB reset, OTA/DFU); shared `ConfirmModal.tsx` with Radio/Modules destructive flows. Local-only OTA/DFU disabled when **Configure node** targets a remote node.
- **Key verification:** `lib/meshtastic/meshtasticKeyVerification.ts` + `stores/keyVerificationStore.ts`; UI `KeyVerificationDialog.tsx` (lazy from App). Firmware 2.7+ handshake; node-detail **Verify key…** / **Key verified** badge. Operator guide: [`meshtastic.md` — Key verification](../meshtastic.md#key-verification).
- **Remote shell:** `lib/meshtastic/remoteShell.ts` / `remoteShellSession.ts` + `stores/remoteShellStore.ts`; Administration **Remote shell (Meshtastic)** (not Reticulum rnsh). Idle close ~10 min; transcript in-memory only. Operator guide: [`meshtastic.md` — Remote shell](../meshtastic.md#remote-shell).
- **XMODEM:** `lib/meshtastic/meshtasticXmodemTransfer.ts` (+ `xmodemFilename` helpers); Radio **XMODEM file transfer** — local USB/serial only (hidden for remote **Configure node**). Operator guide: [`meshtastic.md` — XMODEM](../meshtastic.md#xmodem-file-transfer).
- **Firmware lockdown:** `lib/meshtastic/meshtasticLockdown.ts`; Radio **Firmware Lockdown** (provision / unlock / lock / disable). Operator guide: [`meshtastic.md` — Firmware lockdown](../meshtastic.md#firmware-lockdown).
- **Remote admin module snapshot:** `meshtasticRemoteAdminModuleFetches.ts` — canonical list/count of `ModuleConfig` reads during remote snapshot (`REMOTE_ADMIN_MODULE_CONFIG_FETCHES`).
- **Channel URLs:** `src/shared/meshtasticUrlEncoder.ts` (parse/generate), `src/shared/meshtasticChannelApply.ts` (replace vs add-only apply); Radio panel UI; Meshtastic-only.
- **S&F chat history:** `src/renderer/lib/meshtasticBacklogUtils.ts` — `CLIENT_HISTORY` on primary router heartbeat after RF configure (auto: 50-msg cap, 120 min window cap, 15 min per-server cooldown, 5 min offline gate; `storeForwardAutoFetchHistory` opt-out; `storeForwardHistoryProfile: 'conservative' | 'aggressive'` in `defaultAppSettings.ts` tunes offline gate / cooldown / cap aggressiveness; manual catch-up in Chat). Protobuf decode for replayed text, `via_store_forward` on messages; do not await SDK queue for history (async replay).
- **Delivery proof / SF++:** `MeshtasticProtocol` emits `meshtastic_routing_ack` from `ROUTING_APP` (including `ackProofStatus`); `meshtasticRoutingAckSideEffects.ts` stamps `MessageRecord.ackProofStatus`. Store & Forward++ module frames update `sfppPhase` via `meshtasticStoreForwardPlusPlus.ts` in `meshtasticModulePortSideEffects`. Chat `MessageStatusBadge` prefers proof / SF++ badges when present (`meshtasticAckProof.ts`).
- **Channel security chips:** Chat Meshtastic pills use `channelSecurityBadges.ts` + `ChannelSecurityBadges` (weak/AES128/AES256 PSK, precise location, MQTT uplink) from live `channelConfigs`.
- **MQTT broker clientId:** `src/main/mqtt-broker-client-id.ts` — stable per-install IDs in `app_settings` (`meshtasticMqttClientId`, `meshcoreMqttClientId`); MeshCore LetsMesh `v1_` username unchanged as clientId.
- **PKC remote admin (firmware 2.5+):** `meshtasticRemoteAdmin.ts` — PKI-wrapped `AdminMessage` via `MeshDevice.sendRaw()` (`pkiEncrypted: true`, channel omitted on wire); session passkeys (~300s); tab-scoped snapshot routes in `meshtasticRemoteAdminSnapshot.ts` (Channels-first LoRa load). Per-node keys: `meshtasticRemoteAdminKeyStorage.ts` (`meshtasticRemoteAdminKey:<nodeNum>` in `app_settings`; base64 / `base64:` / 64-char hex paste). Dest public key: NodeDB hex first, stored admin-key base64 fallback. `useMeshtasticRuntime`: `configureTargetNodeNum`, `remoteConfigSnapshot`, `runRemoteAdminOp` (errors → UI + toast); serialize admin reads with S&F (`remoteAdminReadsActiveCount` in `meshtasticBacklogUtils.ts`). **Requires connected local radio** (MQTT-only cannot admin). UI: `ConfigureNodeSelector.tsx`; NodeDetailModal admin key + **Configure node remotely**; SecurityPanel **Copy** public key. Persist last target in `meshtasticConfigureTargetNodeNum`. Gate with `hasRemoteAdmin`. Legacy admin channel (PSK + `"admin"`) out of scope.
- **Meshtastic last heard:** `meshtasticLastHeard.ts` — bump `last_heard` on live RF packets (not only text); `computeNodeInfoLastHeardMs` merges radio NodeDB timestamps with client-side values (max wins). **Configure replay guard** must apply in `nodeStore` (`upsertNode`, `updatePosition`, `meshtasticLastHeardPatch`) via `meshtasticConfigurePhase.ts`, not only in `meshtasticNodeSideEffects` — PacketRouter updates the store before side effects run. During `device.configure()`, the Meshtastic SDK replays NodeDB as `node_info` frames and may emit synthetic `onUserPacket` / `onPositionPacket` with `rxTime = now`; guards skip those bumps. UserPacket path uses `mergeMeshtasticUserPacketLastHeard` (ms); NodeDB path uses `computeNodeInfoLastHeardMs` (sec). **Protocol decode must use `meshtasticPacketRxTimeMs`** — `@meshtastic/core` `PacketMetadata.rxTime` is already a `Date` (ms); never `rxTime * 1000` (Date×1000 → ~1e15; regression lock in `MeshtasticProtocol.test.ts` Date-shaped rxTime + source-policy `meshtastic-protocol-rxtime-via-helper`). SQLite stores `last_heard` as unix seconds; `meshtasticDbCacheHydration.ts` normalizes to ms on hydrate (`normalizeLastHeardMs`); stale/online checks use `effectiveLastHeardMs`. BLE configure uses a **stall watchdog** (`MESHTASTIC_BLE_CONFIGURE_TIMEOUT_MS`, reset on each replayed `node_info` / position / telemetry via `touchMeshtasticConfigureProgress`) so large NodeDBs are not cut off mid-stream. Node list JSON export emits `last_heard` as unix seconds with `last_heard_unit: 'unix_sec'`.
- **Static GPS:** `src/renderer/lib/gpsSource.ts` — the active saved location (App tab **Saved locations**, `lib/savedLocations.ts`) is the static override; it syncs to self-node, map, and radio `setPosition`. Only a radio fix from this session counts as `device` source; static coordinates echoed back by the radio do not. Diagnostics trust rules: [`diagnostics.md`](../diagnostics.md).
- **Firmware 2.7 / 2.8 parity (#1148):** LoRa **Apply** is gated until the `lora` slice hydrates. Long names are capped at **24 UTF-8 bytes** (`src/shared/meshtasticLongNameLimits.ts`). Firmware 2.8 `FromRadio.region_presets` is decoded by `lib/meshtastic/meshtasticRegionPresets.ts` into `meshtasticConfigSlices.regionPresets` (allowed presets, default, licensed-only per region; missing map = unrestricted; cleared on disconnect); Radio panel filters modem presets with it. Bandwidth is sent as the wire code. **Node renumbering:** when a node with a known public key appears under a new number, `lib/meshtastic/meshtasticNodeRenumber.ts` + main `meshtasticNodeRenumber.ts` migrate messages and remote-admin keys only if the new number equals `crc32(public key)` (`src/shared/meshtasticNodeNumFromPublicKey.ts`) and the destination row has no different key. Own-node number history is keyed by the radio's public key and restored from SQLite at startup.
- **Firmware 2.8 inbound decode (#1146):** `patches/@jsr__meshtastic__core@2.6.6.patch` ignores new 2.8 ports (node status, port 36) and `regionPresets` frames, warns once on unknown ones, and guards each decoded frame so one bad packet cannot end the `fromDevice` stream; any pipe failure triggers an immediate reconnect.
- **Mesh Beacon module (2.8):** `ModuleConfig.MeshBeaconConfig` lives in `moduleConfigs.meshBeacon` and is edited in `MeshBeaconModuleSection.tsx` (flags bitfield, 60-byte message, interval ≥ 3600 s, channel/region/preset/slot offer, up to 8 `broadcastTargets`); helpers in `lib/meshtastic/meshBeaconConfig.ts`. `MESH_BEACON_APP` (port 37) payloads are decoded by `meshBeaconCodec.ts` (schema rebuilt from the upstream descriptor because the package does not export it) into `meshtasticRuntime.meshBeacons`. `MeshBeaconHeardList.tsx` offers **Join channel** (first free secondary slot, never the primary) and **Use radio settings** (`meshBeaconJoin.ts` `planMeshBeaconLora`: never changes an already-set region). Join is hidden for remote **Configure node** targets.
- **Status Message module (2.8):** `moduleConfigs.statusmessage.nodeStatus` is edited in ModulePanel; inbound `NODE_STATUS_APP` (port 36) fills `meshtasticRuntime.nodeStatuses`, shown in NodeDetailModal when `hasNodeStatusMessage`. Other 2.8 ports without a published payload schema (paging, S&F++, LoRaWAN bridge, Reticulum tunnel, LoRa OTA, group alarm) are label-only entries in `UNTYPED_MODULE_PORTS`. **Cayenne** remains in that untyped port set for chat labeling, but inbound Cayenne LPP is decoded into `cayenneTelemetryStore` and charted on the Telemetry tab via `CayenneTelemetrySection` (`hasCayenneTelemetry`, Meshtastic only).
- **Declarative extra config fields:** Less common Radio / Security / Module fields (buzzer mode, position flags, GPS / I2S / INA pins, static IPv4, rsyslog, ignore list, FEM LNA, packet signature policy, Audio module, detection trigger, Pax thresholds, health telemetry, range-test clear-on-reboot) are specs in `lib/meshtastic/meshtasticExtraConfigFields.ts`, held by `useMeshtasticExtraConfigFields` and rendered by `MeshtasticExtraConfigField.tsx`. Each section spreads the hook's `result.overrides` into its apply payload; a parse failure (bad IPv4, out-of-range number, bad node id) blocks the apply. IPv4 is a little-endian fixed32 (first octet in the low byte); nested keys such as `ipv4Config.ip` merge into a copy of the device sub-message. Position applies write `positionBroadcastSmartEnabled` (the proto field), and map reports carry `mapReportSettings.shouldReportLocation`.
- **ALERT_APP (port 11):** Decoded as UTF-8 text like `TEXT_MESSAGE_APP` in `MeshtasticProtocol` and MQTT (`mqtt-manager.ts`) so MECP / critical alerts reach chat + `useMecpAlertWatcher`. See [`mecp.md`](mecp.md).

## Delivery proof and Store & Forward++

- Outbound chat rows may carry Meshtastic-only `ackProofStatus` / `sfppPhase` on `MessageRecord` (not in the shared `MessageStatus` union).
- ROUTING_APP ACKs emit `meshtastic_routing_ack` with `MeshPacket.ackProofStatus`; `meshtasticRoutingAckSideEffects` stamps the matching message id (`Data.requestId`).
- `STORE_FORWARD_PLUSPLUS_APP` is decoded in `meshtasticModulePortSideEffects` via `StoreForwardPlusPlusSchema` and correlated by `encapsulatedId`.
- `MessageStatusBadge` shows proven / proof-failed / relayed-unproven / SF++ routing|confirmed. Unknown enums stay neutral.
